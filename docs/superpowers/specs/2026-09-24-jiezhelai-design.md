> 日期：2026-09-24 · 状态：设计已逐段确认，待审阅后写实施计划
> 仓库（待建）：`fjkkx77/Pick-Up` · 本地：`Desktop\AI\VibeCoding\接着来\`

## 0. 要解决的问题

一件事（追剧、学习、工作任务）没法一次做完，中途停下后容易"丢进度"。用户确认以下四种都是痛点：

| 痛点 | 设计上的对策 |
|---|---|
| ① 忘了停在哪个位置 | 每项都有结构化的「位置」（§1.1），打开就能看到 |
| ② 忘了当时的思路、下一步做什么 | 每次停下时留一条「断点笔记」，显示在「接着来」卡片最显眼的位置（§2.2） |
| ③ 忘了这件事还没做完 | 首页按最近碰过排序 + 冷落提醒条（§2.1） |
| ④ 记录太麻烦所以没记 | 两种记录速度：首页 2 秒 +1 / 详情页 20 秒写笔记（§2.4）；不用登录（§3.1） |

**核心定位：不是"记录工具"，而是"下次能无缝接上"。**

使用设备：手机和电脑都会用 → 需要多设备同步，界面按手机优先设计，电脑上也要顺手。

## 1. 数据模型

### 1.1 位置：一套通用结构，模板只是预设

**不为每种东西各写一套代码。** 位置 = 最多 3 层计数 + 可选时间点，每层的单位名自己定。

| 模板 | kind | 预设层级 | 时间点 |
|---|---|---|---|
| 追剧 | `counter` | 季 / 集 | 有 |
| 读书 | `counter` | 章 / 页 | 无 |
| 网课 | `counter` | 节 | 有 |
| 刷题 | `counter` | 题 | 无 |
| 工作任务 | `checklist` | 步骤列表 | — |
| 其它 | `free` | 只有文字 | — |

模板只决定新建时的默认值，建好后层级名、层数、有无时间点都可以改。

规则：
- **总数可以留空**（`total: null`），表示连载中或不知道总数
- 最细一层总数未知：+1 一直往上加，永远不会"到头"
- 最细一层已到总数，再点 +1：
  - 外层总数已知且还没到头（第 3 季 / 共 5 季）→ 进入下一季，内层归 1
  - 外层总数未知（不知道还有没有下一季）→ **不猜**，状态变「等更新」，提示条给出「进入下一季」按钮让用户自己决定
  - 已经是最后一季最后一集 → 状态变「等更新」，提示条给出「标记为看完了」；**不自动标成完成**
- 外层 +1 时，内层都归 1；任何一层 +1 时，时间点清空
- 某一刷还没有任何记录时，位置显示「还没开始」，第一次 +1 得到各层都是 1
- 时间点格式：`mm:ss` 或 `h:mm:ss`；输入框支持直接打数字（`2314` → `23:14`，`10530` → `1:05:30`）

### 1.2 项目（item）

```
{
  id, title,
  kind: 'counter' | 'checklist' | 'free',
  levels: [{ unit: '季', total: 5 | null }, { unit: '集', total: 12 | null }],  // counter 才有
  hasTime: bool,
  steps: [{ id, text }],                  // checklist 才有；勾选状态存在记录里
  status: 'active' | 'waiting' | 'paused' | 'done' | 'dropped',
  round: 1,                               // 第几刷
  link, platform, tags: [],
  type: 'item', createdAt, updatedAt, order, deletedAt  // 后四个是同步内核要求的字段
}
```

**注意：项目本身不存"当前位置"。**

### 1.3 断点记录（log）

```
{
  id, itemId, round,
  at,                                     // 记录时刻
  pos: [3, 7], time: 1394 | null,         // counter：各层当前值 + 秒数
  checked: [stepId, ...],                 // checklist：此刻已勾的步骤
  note: '男主刚发现真相，下集开头别跳',     // 可空
  prevStatus: 'active' | null,            // 这次记录改了项目状态时，存改之前的，撤销用
  type: 'log', updatedAt, deletedAt
}
```

- **当前位置 = 本项目、当前这一刷里，时间最新且未删除的那条记录的位置**
- 每次首页 +1、每次详情页「停在这里」都**新增**一条记录，从不修改旧记录
- 撤销 = 给那条记录打墓碑（`deletedAt`）；如果那次 +1 顺带改了状态（比如变成「等更新」），**撤销时状态一起还原**——所以记录里要存 `prevStatus`
- 「最新一条」按 `at` 比较，`at` 相同时按 `id` 比较，保证两台设备算出同一个结果

**为什么这样设计（用户已确认）**：如果位置直接存在项目上，手机和电脑离线时各点一次 +1，按"逐条最后写入者胜"合并时有一边会被覆盖。改成只追加记录，合并时两边记录都在，不存在覆盖。

### 1.4 派生出来的数据（不存，每次算）

- 当前位置、最新笔记、最后碰过的时间
- 速度估计：取当前这一刷最近若干条记录算"每天推进多少"，结合剩余量得出"约还需 N 天"。**窗口大小取多少待实现时根据真实数据定**；记录太少（少于 3 条或跨度不到 2 天）时不显示，避免给出没依据的数字
- 冷落：状态为「进行中」且最后碰过的时间超过阈值

### 1.5 刻意不做（YAGNI）

评分、封面图、自动抓取剧集信息（要接第三方接口，对"不丢进度"帮助不大）。

## 2. 页面与流程

全站只有 3 个界面。

### 2.1 首页：进度列表

- 顶部**冷落提醒条**：「有 N 项超过 14 天没碰了」，点开列出是哪几项。**14 天是初始值，没有依据**，放进设置可调
- 列表按最后碰过的时间倒序
- 卡片：标题 · 位置（大字，如「S3 · 第 7 集 · 23:14」）· 最新笔记一行灰字 · 「3 天前」
- 卡片右侧大 **+1** 按钮 → 底部提示条 `已记到第 8 集 · 撤销 · 写两句`（撤销有效时间约 5 秒；「写两句」给刚才那条补笔记）
- 顶部标签：进行中 / 等更新 / 暂停 / 已完成 / 弃坑；另可按标签筛选
- 卡片左滑：暂停 / 完成 / 删除（删除二次确认）
- 下拉刷新 = 立刻同步一次

### 2.2 详情页（底部弹出面板，下拉关闭）

1. **「接着来」卡片**：位置 + 最新笔记 + 「去看 ↗」（打开存的链接）
2. 位置调节：每层 − / +，点数字可直接输入；时间点输入框（§1.1 的格式）；checklist 是勾选列表
3. 主按钮 **「停在这里」** → 弹出笔记输入（可不填）→ 生成一条记录
4. 历史时间线（每条：时间、位置、笔记；可删单条）
5. 设置：状态、第几刷（「开始二刷」= round+1，位置从头）、链接/平台、标签、层级与模板

在详情页里调了位置但没点「停在这里」就关掉 → 询问是否保存（照 Apple：有未保存改动时下拉关闭要确认）。

### 2.3 新建：快速小弹层

只问名字 + 选模板，**点开的那一拍里同步调用 `focus()`**（一日轨道踩过：放进 `setTimeout` 后 iOS 只放光标不弹键盘）。其余信息以后再补。

### 2.4 两种记录速度

| 速度 | 做法 | 解决 |
|---|---|---|
| 2 秒 | 首页点 +1 | 痛点④ |
| 20 秒 | 详情页调位置 → 写"下次先做什么" → 停在这里 | 痛点② |

`checklist` 的 +1 = 打开详情页去勾步骤；`free` 的 +1 = 直接打开笔记输入。

## 3. 技术构成

### 3.1 同步：同步码，免登录（用户已选）

- 复用日程卡片的方案：Vercel 函数 `api/sync.js` + Upstash；首次使用生成同步码，另一台设备输入同一个码即共享数据；服务端只存同步码的哈希
- 前端同步内核直接搬 `references/组件_多设备同步/sync-core.js`（已有 28 条自检）
- **项目和记录放在同一个列表里，靠 `type: 'item' | 'log'` 区分**：存档内核的 `syncOnce` 只处理一个列表，这样不用改内核就能直接用；合并仍是按 `id` 逐条进行，记录只追加，天然不冲突
- 记录会越积越多（每次 +1 一条）。单条估计几百字节，几年下来也就几千条，量级不大；**但 Upstash 单个值 / 单次请求的大小上限我没查，待实现前查官方文档确认**
- 换设备：接入存档里的「二维码搬设置」，扫码带走同步码
- 兜底：设置里提供导出 / 导入 JSON

### 3.2 代码结构（按职责拆，逻辑与界面分离）

| 文件 | 职责 | 依赖 |
|---|---|---|
| `assets/model.js` | 纯函数：+1 规则、当前位置推导、速度估计、冷落判断、时间点解析 | 无（不碰 DOM） |
| `assets/sync-core.js` | 从存档搬来的同步内核 | 无 |
| `assets/store.js` | localStorage 读写 + 同步调度（防抖、切走冲刷） | model、sync-core |
| `assets/app.js` + `index.html` + `assets/app.css` | 界面 | 以上 |
| `api/sync.js` | 服务端 | Upstash |

下拉刷新、iOS 手势（左滑 / 下拉关面板）、二维码搬设置从 `references/` 各自的存档搬。

## 4. 边界情况

| 情况 | 处理 |
|---|---|
| 剧更新了，总集数变多 | 改总数时若状态是「等更新」且当前位置小于新总数，自动回到「进行中」 |
| 二刷 | 记录带 `round`；当前位置只看当前这一刷；旧一刷的历史保留可查 |
| 视频超 1 小时 | 时间点支持 `h:mm:ss` |
| 断网 | 本地优先，联网后补同步 |
| 浏览器缓存被清 | 同步码还在就能拉回；另有导出 JSON |
| 两台设备时钟不一致 | 只影响"最新一条"的判定先后，记录本身不丢；并列时按 `id` 兜底保证两台设备结果一致 |
| 手滑多点 +1 | 5 秒内点撤销；过了也能在历史里删那条 |
| 同一项目被两台设备同时编辑设置 | 项目按逐条最后写入者胜，属可接受的覆盖（设置很少同时改） |
