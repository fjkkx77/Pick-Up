# 接着来

> **在线使用：https://pick-up-inky.vercel.app/**
> （自有域名 `jd.wbztl.xyz` 已在 Vercel 上加好，等 DNSPod 加一条 CNAME 就能用，见文末）

一次做不完的事——学习、工作、项目、爱好，什么都行——**停下来就容易忘了做到哪、下一步要干嘛，甚至忘了这件事**。
这个网站只干一件事：每次停下时记一句「**做到哪了 · 下一步做什么**」，下次打开就能无缝接上。

---

## 一、怎么用

1. 点右下角 **＋**，写个名字，点「建好」。**不用选类型。**
2. 建好直接进详情，光标已经在「做到哪了」里：写一句现在的进展，再写一句「下一步做什么」，点 **停在这里**。
3. 以后每次停下，点卡片右边的 **记一笔**，写这两句就行。
4. 下次打开，卡片上最显眼的就是「**下一步**」——回来直接照着做。

| 你遇到的情况 | 它怎么帮你 |
|---|---|
| 忘了当时想到哪、下一步要干嘛 | 卡片上写着「下一步」，详情最上面是上次的「做到哪 + 下一步」 |
| 忘了做到哪个位置 | 需要的话可以加一个**进度刻度**（第几页、第几题、百分比、步骤清单），见下 |
| 忘了这件事还没做完 | 超过 14 天没碰的会在首页顶上提醒你（天数可以在设置里改） |
| 嫌记录麻烦 | 两句话都可以只写一句；有进度刻度的事首页一下 **+1** 就记完 |

### 进度刻度（可选）

大部分事只记文字就够了。有些事有天然的「数」，可以在详情最下面「设置」里点 **加一个进度刻度**：

| 选 | 适合 | 卡片上显示 |
|---|---|---|
| **按数字记** | 看书按页、刷题按题、课程按节、完成度按 % | `第 42/300 页` + 进度条，按钮变成 **+1** |
| **拆成步骤** | 能拆成几步的事 | `2/3 步`，「下一步」自动是第一个没勾的步骤 |

- 单位自己定（点一下常用的，或者自己打）；**总数不知道可以空着**
- 数字可以有两三层（比如「第几章 · 第几页」）：设置里「在最前面再加一层」
- 看视频 / 听课时可以打开「记到几分几秒」：`2314` = 23:14，`10530` = 1:05:30
- 不想要了随时「去掉」，写过的字和记录都留着

### 一些细节

- **+1 到头了**：
  - 这一层到头、但上一层的总数不知道（比如不知道一共几章）→ 不替你猜，先标成「等待中」，提示条上有「进入下一章」
  - 全部到头 → 标成「等待中」，提示条上有「标记为完成」；**不会自动算完成**
  - 把总数改大后 → 自动回到「进行中」
- **撤销**：+1 之后 5 秒内点提示条的「撤销」；过了也行，详情里的记录列表能删单条
- **补一句**：+1 后提示条上点「补一句」，给这一下补上做到哪 / 下一步
- **左滑卡片**：暂停 / 完成 / 删除（删除会先问你）
- **从头再来一遍**：详情里开始新的一轮，上一轮的记录留着
- **状态**：进行中 / 等待中 / 暂停 / 完成 / 放弃；后两种在「归档」里
- **速度估计**：有数字刻度、记录够多时，详情里显示「最近每天约 N 页，照这个速度约 M 天做完」
- **链接 / 标签**：详情设置里可以存一个相关链接、打几个标签（首页可以按标签筛选）
- **往下拉**：首页往下拉 = 同步 + 刷新；弹出的面板往下拉 = 关掉（写了字没保存会先问）

## 二、手机和电脑用同一份数据

右上角 ⚙ → **多设备同步** → 点「生成」→「开启同步」。然后在另一台设备上：

- **扫码**：用手机相机扫设置里的二维码，打开后点「接入」
- 或者点「复制接入链接」发给自己，在另一台设备打开

之后两边自动互通（改完 0.6 秒上传；切回页面、每 30 秒、下拉都会拉取）。

- 同步码相当于密码，知道它的人能看到并改你的记录，别外传；服务器上只存它的哈希
- 两台设备离线时各记了一次，联网后**两条都在**，不会互相覆盖（当前位置取时间较新的那条）
- 删掉的东西会同步删除，不会被另一台设备加回来

## 三、数据存在哪

- **没开同步**：只在当前这个浏览器里。清缓存、换浏览器 → 会丢。
- **开了同步**：本机 + 云端（Upstash Redis）。换设备填同一个码就能取回。
- 不管开没开，都建议偶尔 ⚙ → **导出备份** 存一份 `.json`；导入是**合并**，不会覆盖现有的。
- **换网址 = 换一个本地存储**：浏览器按域名分开存数据。从 `pick-up-inky.vercel.app` 换到 `jd.wbztl.xyz`，本地记录不会自动跟过去——
  在旧网址开同步（或导出备份），到新网址填同一个同步码（或导入）就回来了。

## 五、开发

纯静态前端 + 一个 Vercel 函数，没有构建步骤。

| 文件 | 干什么 |
|---|---|
| `assets/model.js` | 数据逻辑（纯函数，有自检）：进度刻度、+1 规则、当前位置、速度、冷落、撤销 |
| `assets/store.js` | 本地存储 + 同步调度（防抖、切走立刻传、每 30 秒） |
| `assets/app.js` / `app.css` / `index.html` | 界面 |
| `assets/sync-core.js` | 多设备同步内核（取自日程卡片，逐条合并 + 墓碑删除） |
| `assets/gestures.js` / `ptr.js` / `qrcode.js` | 左滑与下拉关闭 / 下拉刷新 / 二维码（均取自已验证的组件） |
| `api/sync.js` | 同步接口（Upstash Redis，零依赖） |

**核心设计**：位置不存在「这件事」上，而是由「最新一条记录」推出来。每次 +1、每次停在这里都**追加**一条记录，
从不修改旧的——所以两台设备离线各记一次，合并就是取并集，谁也不覆盖谁。详见 `docs/superpowers/specs/`。

```bash
node tests/model.test.js                       # 数据逻辑自检
node tests/ui/mock.js "$PWD" 8841              # 本地服务（跑真实 api/sync.js + 内存 Redis 替身）
node tests/ui/flow.js                          # 端到端：功能 + 同步 + 布局（约 6 分钟）
BASE=https://pick-up-inky.vercel.app/ node tests/ui/flow.js sync   # 对线上跑同步
```

部署：Vercel 项目 `pick-up` 已关联本仓库，`git push` 自动部署。
环境变量 `KV_REST_API_URL` / `KV_REST_API_TOKEN` 和日程卡片共用同一个 Upstash 库（键前缀不同，互不串数据）。
